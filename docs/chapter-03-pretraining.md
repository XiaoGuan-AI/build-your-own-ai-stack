# 第 3 章：预训练——把 Transformer 训成会说话的模型

> 目标：亲手完成一次完整的语言模型训练。学完本章，你将有自己训练出的、能生成中文诗句的模型。
> 代码：`code/ch03/train.py`（约 200 行）。**先跑为敬**（CPU 约 10 秒）：

```bash
.venv/Scripts/python.exe code/ch03/train.py --demo
```

你会看到 loss 从 ~4.1 一路降到 1 以下，最后模型生成出像模像样的「诗句」——**这就是第 2 章那个随机乱码的 Transformer 学会说话的过程**。

---

## 3.1 训练到底在干什么？（一句话版本）

> **训练 = 让模型学会预测下一个 token。**

给模型看「床前明月」，让它猜下一个是「光」。猜错了，算一个误差（loss），反向传播算出每个参数该承担多少责任（第 0 章学过），沿负梯度更新一步。重复几千次，模型就「背会」了文本里的统计规律——不只是死记，而是学会了「汉字在什么语境下接什么字」的概率分布。

**语言建模（Language Modeling）** 的正式写法：

```
最大化 P(token_t | token_1, token_2, ..., token_{t-1})
```

对整段文本的所有位置求平均，就是我们要最小化的损失。

**为什么「预测下一个词」就够了？** 因为任何语言能力都可以还原成「根据上下文预测下一个词」：语法（动词后接名词）、知识（「中国首都是」→「北京」）、推理（「因为他饿了，所以」→「去吃饭」）。GPT 系列就是把这个目标做到极致——这就是「预训练」。

---

## 3.2 数据：字符级 + 随机切块

**为什么第 3 章用字符级词表（而不是第 1 章的 BPE）？** 教学取舍：字符级实现最简单（`sorted(set(text))` 完事），把注意力集中在训练本身。BPE 是工程升级——真实模型用它省 token，但训练原理一模一样。你随时可以把第 1 章的分词器接进来。

**随机切块采样**（代码里的 `get_batch`）：

```
语料：床前明月光疑是地上霜举头望明月...
              ↑←— 随机起点 —→↑
     [月 光 疑 是 地 上 霜 举 头 望]   ← 一个训练样本
     [光 疑 是 地 上 霜 举 头 望 明]   ← 目标（右移一位）
```

每步随机选起点，而不是固定滑窗。为什么？**随机性 = 免费的数据增强**：同一段话每次以不同的对齐方式出现，模型见过更多「上下文模式」，天然防过拟合。

---

## 3.3 损失与困惑度

**交叉熵（Cross Entropy）**：对每个 token，模型给出预测分布 p，真实答案是 one-hot。交叉熵 = `-log(p[正确答案])`。猜得越准，值越小。

直觉：loss=4.1 ≈ 平均要从 `e^4.1 ≈ 60` 个候选中猜（我们的词表正好 60+ 字符，等价于瞎猜）；loss=1.0 ≈ 平均只有 2.7 个候选，模型已经相当确定。

**困惑度（Perplexity）= e^loss**：更直观的「平均候选数」。loss 从 4 降到 1，就是「猜 60 选 1 变成 猜 2.7 选 1」。

---

## 3.4 优化器：为什么是 AdamW

梯度下降只有学习率一个旋钮，但真实训练里不同参数需要的步长差很多（embedding 层和 attention 层尺度差异大）。**Adam** 为每个参数维护一阶矩（动量）和二阶矩（自适应步长）——**每个参数有自己的学习率**，快参数慢走，慢参数快走。

**W（Weight Decay）**：把 L2 正则化从梯度里解耦出来，直接衰减权重本身。更稳、更好调。大模型标配。

```python
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.01)
```

---

## 3.5 学习率：为什么需要 warmup

训练初期，模型权重是随机的，梯度巨大且方向混乱。一上来就大步走容易**直接冲出好区域**。所以前几步用很小的学习率「试探」：

```
lr 从 0 线性爬到 3e-4（warmup）→ 之后恒定或余弦衰减
```

教学版简化了（恒定 lr），真实训练（包括第 3 章进阶玩法）建议加 warmup——见练习 D。

---

## 3.6 梯度裁剪：防爆炸的最后一道保险

`clip_grad_norm_(params, 1.0)`：把整批梯度的范数限制在 1.0 以内。万一某个 batch 出现极端值（比如罕见的连续标点），梯度爆炸会毁掉整个训练——裁剪把它挡在门外。**宁可损失一点点更新幅度，也不能让训练崩掉。**

---

## 3.7 训练循环（代码地图）

对着 `code/ch03/train.py` 读，主循环只有 8 行：

```python
for step in range(args.epochs):
    xb, yb = get_batch(data, ...)            # 1. 随机切一坨文本
    logits = model(xb)                        # 2. 前向：预测每个位置的下一个 token
    loss = F.cross_entropy(logits, yb)        # 3. 算误差
    optimizer.zero_grad()                     # 4. 清旧梯度
    loss.backward()                           # 5. 反向：每个参数的「锅」
    clip_grad_norm_(model.parameters(), 1.0)  # 6. 防爆炸
    optimizer.step()                          # 7. 更新参数
    if step % 100 == 0: print(loss)           # 8. 观察
```

**注意看第 2 行的复用**：模型直接 `from transformer import MiniTransformer`——第 2 章手搓的积木，现在派上大用场。这就是「手搓 AI 全栈」的意义：**每一块都是你自己造的，你知道它内部怎么转**。

**checkpoint**：loss 创新低就保存（模型 + 优化器 + 步数）。`--resume` 可以从断点继续。真实训练一次几小时，这功能救命。

## 3.8 观察训练：你会看到什么

跑 `--demo` 时盯着这三个阶段（这就是「学习曲线」的活教材）：

| 阶段 | loss | 生成样本长这样 | 模型在干嘛 |
|------|------|--------------|-----------|
| 起步 | ~4.1 | 完全乱码 | 瞎猜（60 选 1）|
| 中期 | ~2.5 | 「明月光…光…月…」 | 学会了常见字和字组 |
| 后期 | <1.0 | 「床前明月光，疑是地上霜」 | 学会了唐诗结构和常用搭配 |

**为什么 loss 降到 1 就不再降？** 内置语料只有 5 首诗 + 一段白话，模型容量和语料都到顶了——不是它笨，是「题目就这么简单」。想让它更聪明？换更大的语料（练习 B）或更大的模型（练习 C）。

## 3.9 动手实验

1. **换语料**：`--data` 喂任意 txt（比如你的一篇 CSDN 文章），看模型学会「你的文风」要多少步。
2. **学习率对比**：`--lr 1e-5`（几乎不学）vs `--lr 1e-2`（震荡发散）vs `--lr 3e-4`（正常）。画出三条 loss 曲线。
3. **模型大小对比**：`--d-model 32` vs `--d-model 128`，同样步数比最终 loss。观察「容量越大学得越好」的边界。
4. **（进阶）加 warmup**：`torch.optim.lr_scheduler.LinearLR` + `LambdaLR` 组合，前 10% 步数从 0 线性爬到目标 lr，后面余弦衰减。对比有无 warmup 的 loss 曲线。
5. **（进阶）真·预训练**：下载 tiny shakespeare（约 1MB 英文戏剧），用大配置（d_model=256, n_layers=4, block=128, 5000+ 步）在 GPU 上训 1~2 小时——README 承诺的「64M 参数 4090 两小时」路线从这里开始。
