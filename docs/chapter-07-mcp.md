# 第 7 章：MCP 与工具——让 Agent 与世界对话

## 7.1 为什么需要「协议」：从函数到接口

第 6 章的工具注册表有个隐患：**工具和 Agent 是硬耦合的**——Agent 直接调用 Python 函数。一旦工具跑在另一台机器上、由另一种语言实现（比如 Rust 写的文件服务、Go 写的搜索服务），这个耦合立刻断裂。

**MCP 的答案：把工具变成「可描述的远程接口」。** 模型/Agent 不再调用函数，而是：

```
Agent                    MCP 服务器                  真实工具
  │  list_tools()            │                          │
  │ ← 工具清单（含 Schema）  │                          │
  │  call_tool(name, args)   │ → 校验参数 → 调用 →      │
  │ ← 结构化结果/错误        │                          │
```

**协议的价值**：模型侧只认「接口描述」，工具侧只认「参数规范」——两边都标准化了，任何模型 × 任何工具都能组合。这就是为什么 MCP 被 Anthropic 开源后迅速成为 Agent 生态的事实标准。

---

## 7.2 工具 Schema：给工具一张「身份证」

一个工具能用，模型必须知道三件事：**它叫什么、能干什么、参数长什么样**。JSON Schema 风格描述：

```json
{
  "name": "calc",
  "description": "四则运算计算器",
  "parameters": {"expression": {"type": "string", "description": "数学表达式，如 2+3*4"}},
  "required": ["expression"]
}
```

**为什么参数校验必须在协议层做？** 模型可能缺参数、传错类型（把数字传成字符串）——**永远不要相信模型的输出**（第 6 章教训的延续）。校验失败返回结构化错误码（`-32602` 参数无效），模型看到错误后可以修正重试：

```
{"jsonrpc": "2.0", "id": 2, "error": {"code": -32602, "message": "缺少必填参数 'expression'"}}
```

## 7.3 请求/响应协议：类 JSON-RPC

本章协议借鉴 JSON-RPC 2.0（简单、无状态、通用）：

```json
请求：{"jsonrpc": "2.0", "id": 1, "method": "call_tool",
       "params": {"name": "calc", "arguments": {"expression": "2+3*4"}}}
响应：{"jsonrpc": "2.0", "id": 1, "result": "14"}
错误：{"jsonrpc": "2.0", "id": 1, "error": {"code": -32601, "message": "未知工具：foo"}}
```

**`id` 为什么重要？** 异步/并发场景下，响应对应哪个请求靠 id 匹配。教学版同步执行体会不深，但这是协议设计的基本功（真实 MCP 支持流式、批量、跨进程）。

## 7.4 安全护栏：让工具能「碰世界」但不「毁世界」

工具给 Agent 的不仅是能力，也是攻击面。本章的护栏（三件套）：

**① 路径白名单 + 越界检查**：文件工具只允许读项目目录内文件：

```python
p = (self.ALLOWED_ROOT / path).resolve()          # 解析符号链接/相对路径
if not p.is_relative_to(self.ALLOWED_ROOT):       # 检查是否越界
    raise PermissionError(f"路径越界：{path}")     # 防 ../../ 逃逸
```

**② 只读默认**：教学版文件工具只有 `file_read`，没有 `file_write`。**给 Agent 的权限从最小集开始，按需放宽**——真实系统还会用沙箱、权限代理、人工审批。

**③ 输出长度上限**：`[:2000]` 截断——一个 10MB 的文件读进来会把模型上下文撑爆。工具的输出是「模型的输入」，必须按模型窗口管理。

**安全三原则总结：输入不可信（校验）、路径不可越（白名单）、输出不可满（截断）。**

## 7.5 真实 MCP 与本教学版的差距

| 真实 MCP | 教学版 |
|----------|--------|
| 进程间通信（stdio / SSE / HTTP）| 函数调用（同进程）|
| 流式输出、进度通知 | 一次性返回 |
| 资源（Resource）+ 提示（Prompt）体系 | 只有工具（Tool）|
| 授权/审批链 | 无 |
| 官方 SDK（TypeScript/Python）| 手写协议 |

**差距很大，但原理一致**——你在本章手搓的 Schema 校验、错误码、白名单，就是 MCP SDK 内部做的事。**理解协议的本质，比会用 SDK 更重要**（SDK 会过时，协议思想不会）。

## 7.6 动手实验

1. **加一个 `file_write`**（带警告的写操作）：限制只能写 `output/` 目录、限制文件大小、强制要求 `overwrite=true` 参数——体验「权限最小化」。
2. **加 `list_files` 工具**：列出目录内容（同样过白名单），观察工具清单的增长。
3. **协议扩展：批量调用**：`method: "batch"` 一次执行多个 call_tool，返回结果数组。
4. **（进阶）进程间通信**：用 `multiprocessing` 把 server 放到子进程，客户端通过管道收发 JSON——体验真实 MCP 的跨进程模型。
5. **（进阶）接 ch06 Agent**：让 Agent 的 `ToolRegistry` 改成通过 `McpClient` 调用——把硬编码工具换成协议调用。
