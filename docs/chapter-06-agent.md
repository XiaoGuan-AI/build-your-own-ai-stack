## 6.1 什么是 Agent：三个零件

```
┌─────────────────────────────────────────────┐
│  Agent                                       │
│   ┌──────────┐   ┌────────────┐   ┌───────┐ │
│   │ 大脑 LLM  │ → │ 循环 ReAct  │ → │ 工具  │ │
│   │（思考）    │   │（调度）      │   │（手脚）│ │
│   └──────────┘   └────────────┘   └───────┘ │
└─────────────────────────────────────────────┘
```

- **大脑**：决定「下一步做什么」——思考、规划、写行动指令
- **工具**：真正改变世界的部分——算数、查资料、读写文件、调用 API
- **循环**：把两者串起来——思考 → 行动 → 观察 → 再思考……直到给出答案

没有循环，LLM 只会聊天（ChatGPT 的早期形态）；没有工具，LLM 算不出 `2+3*4`（它只会「编」）；没有大脑，工具只是一堆函数。**Agent = 三者组合后的涌现能力。**

---

## 6.2 ReAct 循环：让思考可见

ReAct（Reasoning + Acting）是目前最主流的 Agent 循环范式，核心是**让模型交替输出「思考」和「行动」，格式严格可解析**：

```
Thought: 我需要算一下 2+3*4           ← 思考（给模型自己看的推理过程）
Action: calc(2+3*4)                   ← 行动（工具名+参数，机器可解析）
Observation: 14                        ← 观察（工具返回的结果）
Thought: 结果是 14，可以回答了
Answer: 2+3*4 = 14                     ← 最终答案
```

**为什么格式必须严格？** 模型输出是自由文本，但工具调用需要精确的参数。`Action: calc(2+3*4)` 这种「一行格式」让程序能用正则精确提取——**自由文本 + 结构化指令，是 Agent 世界的通用语言**（OpenAI 的 function calling、Anthropic 的 tool use 本质都是这个，只是格式更规范）。

**为什么先 Thought 再 Action？** 让模型把推理过程「说出来」，而不是直接猜工具——思考路径越完整，工具调用越准确。这也是 ReAct 论文的核心发现：**显式推理显著提升工具调用的正确率**。

## 6.3 工具：Agent 的手脚（和安全问题）

本章三个工具：

| 工具 | 做什么 | 教学点 |
|------|--------|--------|
| `calc` | 四则运算 | **安全 eval**：绝不能让 LLM 的输出直接 `eval()`（它会执行任意代码！）|
| `search` | 知识库检索（第 5 章 RAG）| 工具可以复用前面章节的积木 |
| `now` | 当前时间 | 最简单的「世界接口」 |

**calc 的安全实现**（本章最重要的工程细节）：

```python
# ❌ 危险：LLM 输出直接执行——它可以说 "calc(__import__('os').system('rm -rf /'))"
eval(expr)

# ✅ 安全：AST 白名单——只允许数字和四则运算符，任何函数/属性调用直接拒绝
node = ast.parse(expr, mode="eval").body
# 只处理 Constant / BinOp / UnaryOp，其他类型 raise ValueError
```

**这是 Agent 安全的第一个教训：永远不要把模型的输出当代码执行。** 真实系统还有更多护栏（第 7 章细讲）：路径白名单、权限隔离、沙箱执行。

## 6.4 循环控制：三个关键机制

1. **最大步数**：模型可能陷入死循环（反复调用同一工具）。`max_steps` 强制终止——**宁可失败，不可死循环**。真实系统还会有「预算」（token 上限、时间上限、费用上限）。

2. **解析失败重试**：模型偶尔不按格式输出。解析不到 Action/Answer 时，把「提示」作为 Observation 喂回去，引导模型重新输出。

3. **诚实失败**：步数用尽还没答案 → 明确返回「Agent 终止」，而不是编一个答案。**Agent 的第一原则：不会就是不会。**

---

## 6.5 大脑的诚实讨论（本章最重要的认知）

`agent.py` 提供了两种大脑：

- **脚本大脑（--demo）**：按预置脚本行动。看清循环机制——但它是「提线木偶」，没有智能。
- **小模型大脑（--llm）**：第 3 章唐诗模型。跑一下你就看到：它生成的文本是乱码，解析不出 Action/Answer，最终触发诚实失败。

**为什么？** 唐诗小模型根本没学过「工具调用」这个任务。真实 Agent 的大脑是 **API 大模型**（GPT/Claude/DeepSeek 等）——它们在海量「思考→行动」数据上训练过，天生会 ReAct 格式。

**所以本章的正确理解是**：循环机制（解析/调度/安全/终止）是 Agent 的「骨架」，骨架不会随模型换代而过时；大脑（LLM）是「血肉」，换更聪明的模型，同一个骨架立刻变强。**你手搓的骨架，未来接上任何大模型 API 都能用——这就是第 8 章大作业的架构。**

## 6.6 动手实验

1. **加一个工具**：给 `ToolRegistry` 注册 `length`（返回文本长度）、`reverse`（反转字符串）等，让 Agent 学会用。
2. **改脚本大脑**：写一个「多轮检索」脚本（先 search 再 calc），观察循环的步数变化。
3. **最大步数实验**：`--max-steps 1` 跑 demo，看诚实失败长什么样。
4. **（进阶）让 calc 支持变量**：`calc(x=5; 2*x+1)`——需要扩展 AST 解析支持赋值。
5. **（进阶）接真实大模型 API**：把 `LLMBrain.act` 改成调 DeepSeek API（第 0 章环境里配过 key），同一个 Agent 骨架立刻变聪明——验证「骨架不变、大脑升级」的架构。
