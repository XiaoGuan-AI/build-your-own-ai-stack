## 8.1 大作业目标与验收标准

**题目**：不引入任何新的外部 AI 库（PyTorch 除外），用前 7 章的手搓积木做一个命令行 AI 助手。

**验收标准**：

| 能力 | 验收动作 | 走哪条路 |
|------|---------|---------|
| 对话 | 问「你好」得到回应 | 路由 3：生成 |
| 算数 | 问「2+3*4 等于多少」得到 14 | 路由 1：calc 工具 |
| 知识 | 问「什么是梯度下降」得到知识库内容 | 路由 2：RAG |
| 命令 | `/help` `/tools` `/quit` 正常工作 | 命令处理 |
| 诚实 | 模型生成失败时如实说明 | 兜底路径 |

**评分维度**（自己给自己打分）：机制完整 60 分 + 边界处理 20 分 + 代码整洁 20 分。

## 8.3 问题路由：规则路由 vs 模型路由

助手的第一步是「判断这是什么类型的问题」。本章用**规则路由**（正则匹配），简单可靠：

```python
if 含数字 and 含运算符:      → calc 工具     # 数学题
elif 知识库检索相关度 > 0.02: → RAG          # 知识题
else:                       → 生成          # 闲聊
```

**为什么不用模型路由（让模型判断问题类型）？** 教学版的小模型判断不准；而且规则路由**零成本、零延迟、可调试**——对确定性的分类（含不含数字），规则永远比模型可靠。

**真实产品怎么做？** 两者结合：规则处理「确定类型」（命令、数学、日期），模型处理「模糊类型」（意图识别、任务拆解）。**规则兜底 + 模型增强**是工业界的标准姿势。

---

## 8.4 三个关键设计决策

**① 数学题先去噪再算。** 「2+3*4 等于多少」不能直接丢给 calc（表达式里混了中文）。正则剥离「等于多少/是多少/？」，剩下的才是表达式——**用户输入到工具参数的「翻译层」，是 Agent 产品的日常**。

**② RAG 命中阈值。** `hits[0][2] > 0.02`：相似度太低就不走 RAG，防止把无关知识硬塞进回答（第 5 章实验 3 的「检索噪音」）。**阈值是调出来的，不是拍出来的。**

**③ 生成结果的「去复读」。** 小模型会复读 prompt（第 5 章验证过），`text.split("A: ", 1)[1]` 剥掉 prompt 尾巴再展示。**产品视角：用户看到的永远是「回答」，不是「模型的原生输出」——这层清洗在真实产品里叫 post-processing。**

**诚实说明（务必读完）**：这个小模型的「闲聊」回答质量很低（唐诗训练模型的宿命）。**大作业的价值在「架构完整」，不在「回答聪明」**——把 `_generate` 换成 API 模型（8.6），同样的架构会给你惊喜。

## 8.5 代码地图

| 函数 | 职责 | 复用的积木 |
|------|------|-----------|
| `answer()` | 路由分发 | — |
| `_generate()` | 生成（统一出口）| ch02 模型 + ch04 推理 + ch01 分词 |

**读代码时盯一个点**：`answer()` 的三个路由分支如何共用同一个 `_generate()` 出口——这是「统一出口」设计模式：不管哪条路，最终都回到生成，方便将来统一替换大脑。

## 8.6 扩展方向（通向真产品）

1. **换 API 大脑**（10 分钟实验）：`_generate` 里调用 DeepSeek API（第 0 章配过 key），其余代码不动——同一个助手立刻能聊、能答、能干活。
2. **加记忆**：把对话历史存进列表，拼进 prompt（多轮上下文）。
3. **加 MCP 工具**：把 ch07 的 `McpClient` 接进来，助手就能读写文件（白名单内）。
4. **换大模型**：用第 3 章进阶玩法（64M + 大语料）训一个更强的本地模型，`--ckpt` 直接换。
